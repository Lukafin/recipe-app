# AGENTS.md

## Project overview
- Compose Multiplatform recipe app targeting Android, iOS, Desktop, Web (WASM), TV, and Android Automotive.
- UI and navigation live in `shared/src/commonMain/kotlin`; platform modules (`androidApp`, `desktopApp`, `webApp`, `tvApp`, `automotiveApp`, `iosApp`) are thin shells.
- GitHub Pages is served from the `docs/` directory generated by the web/WASM build—treat its contents as build artifacts.

## Setup
- Use JDK 21; Android SDK/NDK via Android Studio with compileSdk/targetSdk 35 and minSdk 24 (see `gradle.properties`).
- For iOS, install CocoaPods and open `iosApp/iosApp.xcworkspace` after running `pod install` in `iosApp/`.
- Optional: create a virtualenv and `pip install requests` if you need to run `sentry_webhook_server.py`.

## Build and run
- Fast sanity check: `./gradlew check` (compiles multiplatform targets).
- Desktop preview: `./gradlew :desktopApp:run`.
- Android builds: `./gradlew :androidApp:assembleDebug` (similarly `:tvApp:assembleDebug` and `:automotiveApp:assembleDebug`).
- Web/WASM dev server: `./gradlew :webApp:wasmJsBrowserDevelopmentRun`.
- Web distribution/GitHub Pages: `./gradlew :webApp:wasmJsBrowserDistribution` then sync the generated `build/dist/wasmJs/productionExecutable/` output into `docs/` instead of hand-editing those files.

## Testing
- There is no dedicated test suite yet; rely on `./gradlew check` for now.
- If you add features, prefer adding multiplatform tests under `shared/src/commonTest` or platform-specific tests to keep regressions out.

## Code style and conventions
- Kotlin official style; Compose UI with navigation driven by `RecipeAppScreen` in `shared/src/commonMain/kotlin/App.kt`.
- Reuse theming helpers like `getFontFamily()`/`getTypography()`; keep platform-specific code minimal and defer shared logic to `shared`.
- Avoid manual edits to generated or vendored content (`docs/`, `node_modules/`, `build/`, `iosApp/Pods/`); regenerate with the appropriate build tool instead.
- Keep secrets out of version control. `.env` and `local.properties` are for local values (API keys, SDK paths); do not expose or commit real keys.

## Automation and ops notes
- `.github/workflows/weekly-readme-update.yml` and `.github/workflows/monthly-maintenance.yml` launch Cursor background agents; keep prompts in `.github/scripts/prompts/` and the Bash helper intact when modifying automation.
- `sentry_webhook_server.py` listens at `/webhook` and forwards crash prompts to Cursor using `CURSOR_KEY` plus optional overrides (`CURSOR_REPO`, `CURSOR_BRANCH`, etc.). Ensure it continues to run without additional dependencies beyond `requests`.
- GitHub Pages relies on the `docs/` output; update it via the web/WASM build rather than manual tweaks.
